# 技术设计

保留现有框架和包管理器。新模块位于 `apps/web/lib/ai`，路由使用 `/[locale]/ai/architecture`、`/[locale]/ai/pricing`、用户内部 `/api/ai/*` 和受保护 `/api/admin/ai/*`。普通工具路由不变。

## 持久化

复用现有 SQLite 所在持久盘，使用独立 `ai_*` 表、幂等 schema 迁移、WAL 和短事务。用户账户与管理员表隔离。账本是事实来源，余额为同事务维护的可核对缓存；积分使用整数毫积分，金额使用整数货币最小单位。事务内不进行网络 I/O。

配置发布、报价、付款商品金额与积分额度在任务/订单上记录不可变快照。配置乐观锁，变更历史保留；发布/回滚遵守部署安全上限。真实秘密加密存储、仅显示已配置状态，密文和主密钥不随普通运营备份导出。

## 任务与资金

网页 → 鉴权/输入校验 → 原子冻结积分并写任务/待投递记录 → 限流 Worker → 供应商 → 验证输出 → 持久授权资产 → 原子结算 → 下载。

网络未知状态不等于失败；已发送供应商请求不能仅因进程重启重新生成。任务记录外部 ID、阶段与幂等键；使用可恢复 claim/租约和对账，明确不支持真实中止的供应商限制。积分必须能从不可变流水重新核算。后台调分也必须有原因、操作者和幂等键，不直接改余额。

支付渠道各自验签、验证环境/商户/产品/金额/货币、幂等消费事件；服务器创建订单并关联付款主体。回调到达才入账，成功返回页只能查询状态。退款和争议与原授信流水关联，未使用额度回收，已消费额度明确处理，不能伪造退款成功。

## 供应商安全

支持受控的已实现协议适配器，不提供任意脚本。后台 Base URL 受 HTTPS、公网 DNS、允许主机和响应体大小约束；阻止私网/元数据地址、重定向窃取密钥及任意远程图片代理。服务端秘密以独立部署主密钥加密。参考图通过 MIME/签名/解码/像素/数量预检后上传；外部结果同样校验。

## UI

沿用 HXSL 品牌、字体、蓝色交互、语义主题变量。侧栏控制建筑用途、面积/房间描述、风格、模型、参考图和明确积分报价；结果区展示真实阶段、图像、成本、继续修改与下载。移动端按输入、参数、结果顺序单列，不使用无限画布。无供应商时说明未配置，不填充假结果。
