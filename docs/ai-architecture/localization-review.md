## 第六批：韩语、泰语与完整语言集合（2026-09-08）

## 第五批：德语、法语、意大利语（2026-09-08）

补充测试证据缺口：`scrollIntoViewIfNeeded`在标题刚好位于视口底部时不会继续滚动，因此标为“references”的截图可能仍只有参数区。仅对这类截图使用`scrollIntoView({block: "start"})`，重新运行并查看完整上传、外部处理说明、同意框、保留期限和生成按钮。实际应用滚动行为不变，不修改处理、上传或结算断言；没有把第一次未拍到的内容称为视觉通过。

## 第四批：西班牙语、巴西葡语与多行标签（2026-09-08）

1. 根因 D/E（测试缺口/隐含假设）：参数 Grid 默认拉伸单元格，但内部 label/select 仍按文档流顶端排列。葡语数量标签在 390px 折成两行，分辨率标签只有一行，两个 select 高低错位。第一轮全部 7 组/13 图通过，肉眼审查发现问题：仅测页面溢出与选中项字宽不能证明相邻控件对齐。

3. 修复位于实际 `.ai-fields` 布局：`align-items: end` 对齐同排控件，保留完整标签及单列自动回流，不设置固定标签高度、不缩短译文。扩充 360/768px 截图后又发现：360px 葡语风格选项挤成四行；768px auto-fit 可产生四列，跨全部列的模型/质量项阻止空轨道折叠，只有两个参数却占半行。保留两张 before 图，新增断言在旧构建以 `es-workspace-768-light two fields must use the full grid row, without empty columns` 失败。风格 flex basis 增至 110px；参数最小轨道取 150px 与半行宽中的较大值，并限制为容器宽，既最多两列又可窄屏单列。断言检查同行纵坐标与占满整行、风格卡片不超过 80px，仍保留溢出、axe、选中项字宽。最终复跑结果见 validation.md。
4. 相似风险：后续德语、法语与手机缩放也可能出现多行标签；不要把两种新语言通过宣称全语言 WCAG/缩放完成。本次测试脚本独立严格 typecheck 还发现原 Sharp CommonJS 类型多用了 `.default`，改为实际模块类型，运行时调用不变。新布局断言首版在不含表单的定价页等待 `#ai-count` 超时，改为先判定实际元素存在；不跳过工作台断言或其他页面 axe 检查。

巴西葡语使用 `pt-BR`，不是 `pt-PT`。遵循 [Unicode CLDR 48](https://www.unicode.org/cldr/charts/48/supplemental/language_plural_rules.html) 的实际数词规则，`0 crédito`、`1,234 crédito` 与西语 `0 créditos`、`1,234 créditos` 不同。整数毫积分不改，单测覆盖 0/0.001/1/1.001/1.999/2/5/1000000/负值，浏览器发布 1/2/5/1.234 套餐独立检查真实文案，不用被测 helper 计算预期值。通用西语与巴西用语为源代码翻译，尚未经过人工母语审校或国家级法律审核；不添加文化评分、当地支付/汇率/认证的无证据声明。

## 第三批：荷兰语、波兰语与积分词形（2026-09-08）

### 根因与失败证据

- E/D（隐含假设与测试缺口）：旧 `aiCreditLabel` 只按英语单复数处理，套餐模板直接写死复数。波兰语的 1 / 2 / 5 / 1.234 不能共用一个单位词形，整数余额测试也不覆盖小数报价。
- 第一版使用 URL 的 locale 选择 Intl 规则；新增回退测试实际得到 pt-BR 英语正文中的 `0 credit`，19 项中 1 项失败。URL 语言不一定是实际文案语言，不能通过只测完整译文掩盖回退问题。

### 修复与防线

- 词典增加 `creditLocale`（实际文案语言）及 one/few/many/other 四种单位词形，字段类型仍可检查。`aiCreditLabel(copy, units)` 在实际文案语言上使用 Intl.PluralRules；显示数值仍用用户 locale。不读取金额字符串、不修改毫积分账本，不把几何风格显示名称写回模型参数。
- 所有已接入词典的 `cycleCredits` 改用 `{credits} {unit}`；真实套餐组件显式传入单位，英语 1 credit 同步修复。无词形变化的中文、日语、土耳其语、越南语保持原单位。
- 单测覆盖 nl/pl 零、单数、少数、多数、12/14/21/22/101/102/112、小数、负值，以及所有未完成语言的英语回退。原有键集合/安全/变量/账本断言保留；修复后词典与客户端 26 项通过。
- 生产浏览器脚本增加真正发布 1 / 2 / 5 / 1.234 积分套餐并读前台文本的断言，独立写出预期词形，不调用被测 helper 算期望值。发布套餐不得改变已有钱包。最终执行结果见 `validation.md`，这里不以脚本存在代表已运行。
- 首次生产浏览器 7 组通过后，真实截图发现手机质量选择器将 Automatisch/Automatyczna 截断：页面无水平溢出不等于原生 select 的文字完整。保留 `before/*-quality-clipped-390-dark.png`，模型与质量改为整行，数量/分辨率使用最小 150px 的自适应列，小容器退成单列；不缩短译文或删减选项。截图检查新增 Canvas 实测选中项文字宽度，扣除控件 padding 和原生箭头预算。

### 规则与剩余范围

规则依据 [Unicode CLDR 48 plural rules](https://www.unicode.org/cldr/charts/48/supplemental/language_plural_rules.html)：荷兰语整值 1 为 one；波兰语区分 one/few/many，非整数为 other。积分显示最多三位小数，复数选择使用相同精度；单位词形不是货币换算。实际语言质量仍待人工母语审校。

后续语言需继续验证句式中的数量、期限、支付确认与长按钮；不能把积分词形完成扩展成所有复数/全部语言完成。按缺陷复盘技能将约定落到本文件和可执行测试；没有 Git/Trellis 模板，因此不伪造提交或模板同步。

## 第二批：土耳其语、越南语与小数显示（2026-09-08）

1. 根因 E/D：原 `displayCredits` 固定 en-US；之前英语和中文以及整数测试不能暴露本地化小数差异。只接入字典仍会留下余额、报价和流水中的英文数字格式。
2. 修复位于实际格式化函数与所有前台调用点：增加可选 locale；默认保持原行为以兼容管理员数字编辑。不改 CREDIT_SCALE、creditUnits 解析、数据库或财务算法。全局搜索调用点后确认没有把该函数当作接受数组下标的 map 回调使用。
3. 防线：土耳其语/越南语字段与格式单测，最小毫积分/负值/最大值；实际生产浏览器 1234.567 积分余额、1.234 单价、冻结两份、部分成功仅扣一份，比较真实整数账本与前台逗号小数。价格仍是 USD，不按语言改币种。
4. 测试自身问题：首次组合参数化错误导入了 Registry 不导出的 isLocale，实际位于 `lib/i18n.ts`；其次 Playwright 字符串 hasText 对大小写不敏感，MP 同时匹配 `example.com` 的 mp，改为完整、区分大小写的单位正则。均保留原断言，不把定位失败归因于应用处理失败。
5. 扩展：后续欧洲语言还需复数规则，不因两种不需数词后复数变化的语言通过就宣称全部语言完成。模型/方案名和测试输入是保存内容，不通过自动翻译修改技术 ID、真实价格或用户描述。
