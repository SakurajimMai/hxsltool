# Bug Analysis: 过时导入预检与截图状态

## 1. Root Cause Category

**B / D：跨层状态契约和视觉测试证据不足。** 服务端 revision/指纹已经拒绝过时导入，但初版前端在 409 或真实提交后丢响应时仍保留「确认导入为草稿」。管理员可能重复尝试无效操作；部分手机截图只显示模块标题，不能证明差异和错误可读。

## 2. Why Fixes Failed

不是改变断言求绿：第一轮流程已经能拒绝并发冲突，真实截图暴露过时确认入口。修复后新增断言确认错误状态中旧确认按钮消失。截图锚点另改为模块/差异/完整错误组件，并等待控件恢复可用、完成主题过渡，避免截取过渡灰色并误当作稳定样式。

## 3. Prevention Mechanisms

| 优先级 | 机制 | 实际措施 | 状态 |
| --- | --- | --- | --- |
| P0 | 服务端 | 导入重新 schema 验证并匹配完整档案/当前 revision 指纹；同事务草稿与审计 | 已实现/17 项测试覆盖 |
| P0 | 前端 | 请求失败后清旧预检/确认；丢响应提示可能已保存，引导读取核对；不自动重发/发布 | 已修复，真实 UI 丢响应验证 |
| P1 | 编辑保护 | 有未保存修改时禁止导入；请求期间锁定配置表单，卸载取消观察请求 | 已实现/浏览器验证 |
| P1 | 证据 | 桌面/手机完整差异和错误截图、稳定主题、键盘焦点及组件 axe | 9 张最终截图和 6 组流程 |

## 4. Systematic Expansion

- 「预检通过」不代表已写入、发布或外部模型/收款认证；UI 和返回状态分开表达。
- 指纹不是管理员权限，也不是档案真实性签名。来源版本不被当作本机主键；未知字段不能偷偷导入密钥或账户。
- 本轮复用已有流式 `readAiBody`，未使用只按字符串长度检查且先整体读入的旧管理 JSON helper。其他管理接口请求体统一改造是另一个明确工作项，不在此处顺带重写。
