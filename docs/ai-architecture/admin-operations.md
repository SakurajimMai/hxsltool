# 建筑 AI 运营操作

此文描述已实现的运营模块，不是整个建筑 AI 产品的最终验收。支付、真实供应商/Google 联调及容器重建仍见 `implement.md` 待办。

## 管理路径

管理员登录 `/admin` →「建筑 AI」：

- 「模型、提示词与套餐」：模型能力、积分费率、全局/风格提示词、套餐新增/移除、草稿、发布、版本回滚、只写加密供应商密钥。
- 同页「AI 配置备份与导入」：导出已发布/已保存草稿 JSON；预检差异与本机依赖后确认写新草稿，再单独发布。不会导出密钥表、账户、订单、账本、用户生成请求或图片。详见 [配置归档说明](config-archive.md)。
- 「用户、积分与任务」→「用户与积分」：按用户 ID 或完整邮箱查询，邮箱默认脱敏；分页查询可用/冻结积分及流水，核对账本一致性。
- 「生成任务」：按任务/用户 ID、状态筛选，查看模型、原报价、已验证/已结算图片数、版本、时间、去敏错误码和待清理结果数量。
- 「AI 操作记录」：查看操作者、动作、对象和时间。不回传任意审计 JSON、描述、图片、下载授权或供应商原始响应。

已有文件工具仍免公众登录，AI 运营模块不采集这些本地工具的使用量。

## 调分

先打开目标账户账本，核对可用/冻结积分与流水，选择补偿、赠送、补发或扣回。输入正数积分（最多三位小数），扣回方向由原因决定。填写 5–64 位字母/数字/点/横线/下划线组成的核对记录编号，勾选确认后提交。

核对记录编号应指向实际内部工单/记录，不放邮箱、密码、文件内容或 token。系统不假称已连接外部工单服务。

金额以整数毫积分存储。扣回不能透支或动用冻结积分；服务端再次验证。账户变更、不可变流水和调分审计在同一 SQLite 事务提交。重复请求 ID 不重复入账，不同内容复用同一 ID 会被拒绝。

网络响应丢失时，页面保留本次参数和请求 ID，使用「核对 / 重试同一操作」。若离开/重载页面丢失待核对提示，必须先查账本与审计，不重新发起同额调整来“试一下”。不要将调分当作支付或退款的证据。

## 任务处理

- **排队取消**：仅限尚未被 Worker 领取的任务，事务内重新核对状态、释放冻结积分。Worker 已领取时拒绝，不伪装成停止上游请求。停用账户的已有排队任务也可由管理员取消。
- **未知状态**：不自动重发，不仅因 HTTP 超时就释放积分。管理员须先查看供应商控制台/支持记录，最早在任务领取 15 分钟后操作；该窗口与 Worker 恢复策略共用同一个常量。
- **确认没有可交付结果**：仅未知任务、无已验证输出时允许，释放冻结积分并记录 `ADMIN_CONFIRMED_NO_OUTPUT`。此动作不代表供应商退款；上游成本由运营人员另行核对。
- **按已验证结果结算**：仅从私有资产的验证记录读取数量，不允许手填成功张数或导入“成功”标记。部分有效输出只收取有效张数费用，即使图片后来过期，财务事实仍保留。
- **晚到结果**：手工结算后，存储层重新核对终态并拒绝新的输出写入；不会重新改变账本或重复收费。

所有任务操作需要近期管理员验证、CSRF/来源校验、确认及核对记录编号。状态改变会拒绝旧页面提交，幂等重试保留审计且不重复结算。当前同步 Images 适配器没有已验证的供应商远程取消/查询 API，不提供通用重试或强制取消运行中任务按钮。

## 文件清理与隐私

「清理到期残留」仅处理已经到期或主动删除的图片，每次最多 100 个，实际删除失败会计数，不用前端倒计时宣称完成。不接受目录路径，不延长原保留期，不删除账本或历史订单。该操作不可恢复已移除文件。

后台不提供用户文件浏览器。技术模型和版本可以查看，用户生成描述、参考图、结果正文、Google subject/令牌、下载授权、秘密密文/明文及上游原始错误响应都不应出现在运营响应或截图。

## 持久化与部署

- 新增 schema v2 只补建 `ai_admin_operations` 幂等操作表与迁移记录，不清空旧表，不改变既有任务/订单/配置版本；既有 AI 表仍使用同一管理员 SQLite 持久盘。
- `HXSL_ADMIN_DB_PATH`、`AI_ASSET_DIR` 需指向持久卷。密钥与 `ADMIN_SESSION_SECRET` 由部署层提供。WAL 快照/新路径离线恢复已局部演练，见 `backup-restore.md`；不把它或进程重启替代容器更新/完整财务灾难恢复证明。
- Next standalone 已排除 `.data`、SQLite、`.env*` 与默认私有图片目录。运行数据库/秘密不能随构建镜像复制，正式部署时另行挂载。新增自定义存储目录时仍需检查构建上下文与跟踪清单。
- `pnpm test:ai:standalone` 使用显式临时数据库、127.0.0.1:13317 与 13320 的隔离 HTTPS 反向代理，验证真实 Secure Cookie、发布/回滚原始 HTML、重启持久化和产物秘密排除。自签名证书只由此测试客户端信任；不关闭应用 TLS 校验。
- 已有/将来财务流水产生后，不直接用旧数据库覆盖现库以“回滚版本”。代码回滚与财务恢复是不同流程，恢复需要离线备份核对与后续流水对账。

## 测试

付款争议另见[PayPal人工积分核对](paypal-settlements.md)：后台支付页可以在近期认证、金额上下限、全部案例核实和版本锁下记录整笔权益总额；不会操作PayPal资金，不把人工确认伪称自动验款。新退款/复议使旧审批失效，原历史保留。Schema7升级/兼容回退规则不能沿用早期schema2的假设。

- `pnpm test:ai`：账户/账本/权限/真实图片验证等合同测试。
- `pnpm test:ai:operations`：新建隔离数据库和本地 Next 实例，真实后台 HTTP/UI 调分、网络断线幂等、权限、取消、人工核对、物理清理及套餐草稿；包含桌面/手机/深浅主题截图与 axe。
- `pnpm test:ai:archive`：真实配置 JSON 下载解析、预检、草稿导入、发布/回滚原始 HTML、并发冲突/丢响应恢复、权限及桌面手机截图。
- `pnpm test:ai:standalone`：先执行隔离 `pnpm build` 生成 `.next-ai-build`；该脚本只启动此构建，不使用公网服务。

测试账号、图片及核对记录均为合成夹具，不能作为真实 Google 登录、实际供应商输出或付款结算证明。脚本运行结束只关闭自身创建的进程。
