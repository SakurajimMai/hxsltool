# 建筑 AI / 管理数据备份与离线恢复

本流程使用原有 Node/SQLite，不引入 Python、外部数据库或公众 CLI 产品。仅限持有主机维护权限的管理员；不是网页文件处理入口。2026-09-08 已在随机 `/tmp/hxsl-ai-backup-*` 隔离目录用合成数据演练，未读取/复制正式数据库、未停止任何应用、未切换线上路径或恢复生产卷。

## 两类导出不能混淆

| 类型 | 内容 | 使用方式 |
| --- | --- | --- |
| 后台普通运营 JSON | 文件工具的运营设置、多语言内容与版本；不包含账户、会话、MFA、AI 秘密/任务/资产 | 后台受保护导出/导入草稿。AI 模型/提示词/套餐现有单独版本化档案，见 [AI 配置导入导出](config-archive.md)，不混入旧工具 JSON 格式 |
| 本文完整 SQLite 快照 | 管理员密码哈希/MFA、用户资料、会话记录、AI 加密供应商密钥、发布/草稿、订单、账本、任务及尚未过期的私有请求 JSON | **敏感维护备份**，不可作为“无秘密导出”分享；严格访问控制和独立加密存储 |

数据库不包含供应商密文解密所需的部署主密钥；该密钥须通过独立秘密备份流程保留。不要把密钥放入备份命令、报告、聊天或普通运营 JSON。数据库快照不会复制 `AI_ASSET_DIR` 图片文件、公开媒体、部署环境文件，也不自动延长图片或任务保留时间。

完整数据库副本会保留快照当时尚未清理的用户请求内容。不能将其无限归档或当作用户云盘；必须纳入隐私告知、访问审批、加密和备份到期清理制度。文件模式 0600 **不是加密**，脚本也没有实现远端备份、自动加密或自动保留策略。部署尚未配置这些控制时，不应启用生产定时备份。

## 一致性与路径规则

- 原脚本只 `copyFile` 主库：实测会遗漏开放 WAL 中已经提交的用户/配置/积分数据。现在使用 Node `sqlite.backup`，在独立只读连接中固定一个读事务快照；源连接和其他写连接保持工作。
- 需要 Node **22.16+ 的 22.x**；本次实际 22.23.2。没有扩大或升级应用技术栈。旧版 Node 不提供该接口时拒绝执行。
- 必须显式提供**绝对**源库和目的路径，不从当前目录猜 `.data`。Next 开发进程通常在 `apps/web` 运行，根目录维护命令的默认路径原本可能指向另一库。Compose 实际路径见 `compose.yaml`，当前容器内为 `/var/lib/hxsl-admin/admin.sqlite`。
- 源必须为已存在、非符号链接的普通文件。目标必须不存在，其 `-wal`、`-shm`、`-journal` 也必须不存在。脚本不覆盖旧备份，不覆盖运行库，不删除残留 sidecar。
- 目标父目录必须为非符号链接的私有目录（0700）；缺失目录按 0700 创建，不擅自 chmod 用户既有目录。目标必须位于所有静态网站目录、公开媒体目录及反向代理文件映射之外；权限位不能阻止以相同 UID 运行的文件服务器公开敏感备份。
- 临时文件在目标盘的私有新目录生成，验证 `integrity_check`、外键、HXSL 核心表、支持的 AI schema 1–7 / 对应支付迁移表，以及余额与不可变账本一致性。v6新增PayPal争议金额与不可变观察历史；v7新增不可变人工付款权益核对。未来 schema 由维护脚本显式适配，不能盲目向旧应用恢复。

### v7 回滚边界

已接收 v7 人工积分核对后，不得直接用只理解 v6/v5 的旧镜像继续处理付款或生图；旧代码不识别新的有效权益状态。优先前向修复或使用同样支持 v7 的上一镜像。确需降级时必须离线恢复到新路径、核对快照之后的真实商户事件和生图任务后再开放。最新v7两镜像重建、兼容回退、非空审批恢复已在隔离环境验证，见 [容器演练](container-rehearsal.md)；不是跨旧schema降级或真实商户故障窗口恢复证明。不得删除历史表或现有卷以绕过版本校验。详见 [人工核对契约](paypal-settlements.md)。
- 验证后的数据库转为独立单文件，0600、fsync、SHA-256；同盘 hard link 原子发布且禁止覆盖。文件系统必须支持 hard link / fsync；不满足时失败，不降级为可能覆盖目标的复制。
- 输出报告只含状态、字节数、schema、校验和及会话撤销数量；不输出用户名称、提示词、密码、凭据、授权 token 或 SQL 行。

依据：[Node 22 SQLite backup 官方契约](https://github.com/nodejs/node/blob/v22.23.0/doc/api/sqlite.md#sqlitebackupsourceDb-destination-options)、[SQLite Online Backup API](https://www.sqlite.org/backup.html)。官方网页访问失败后使用 Node 官方仓库源文档核验，未按不确定记忆实现接口。

## 生成备份

以下是示例路径，必须先由操作者映射到实际持久盘和**新的**私有备份路径。不要直接将宿主机根目录或 Docker socket 挂载进应用。

```bash
HXSL_ADMIN_DB_PATH=/srv/hxsl-data/admin.sqlite \
  pnpm admin:backup /srv/hxsl-private-backups/pre-update-20260908.sqlite
```

`snapshot-verified` 表示当前输出已通过快照与数据库校验，不表示已经上传到异地、加密、验证恢复到生产或容器重建通过。保留报告校验和以及精确应用版本/镜像摘要；备份文件与摘要须分别保存在可信维护记录中，摘要不是签名。

不要把陌生人上传的 SQLite 传入此维护命令。Schema 检查不是恶意 SQLite 沙箱；完整数据库只能来自已确认的本站维护备份。

## 离线恢复到新路径

```bash
CONFIRM_ADMIN_RESTORE=yes \
AI_DISPATCHER_ENABLED=false AI_PAYMENTS_ENABLED=false \
HXSL_ADMIN_DB_PATH=/srv/hxsl-recovery-20260908/admin.sqlite \
  pnpm admin:restore /srv/hxsl-private-backups/pre-update-20260908.sqlite
```

成功状态 **`prepared-offline`**：生成了新的可打开数据库，不代表应用已切换、不代表已恢复收款。旧数据库/原备份均不修改。恢复副本撤销管理员和 AI 用户旧会话，移除未完成 OAuth state，并写入去敏恢复审计；账户、历史、草稿、发布版本、不可变账本、冻结报价、任务状态和原过期时间保留。

命令中的两个 `false` 是操作者离线确认，**不能检测或停止其他进程、阻止另一个进程启动、断开实际 webhooks**。准备阶段不要把新路径提供给接受公众请求的应用。工作进程和回调都应在部署/网络层隔离；仅关闭 `AI_PAYMENTS_ENABLED` 不会停用既有支付回调和取消操作。

恢复上线前必须执行：

1. 隔离恢复环境网络与流量，禁止供应商投递、支付 webhook 和公众写入；使用与备份相容的应用版本。为当前数据库另做最新保护快照，保留原库及其 sidecars，不直接覆盖。
2. 核验应用版本、校验和、schema、运营硬限额、独立主密钥以及供应商槽位解密；旧版本中的密码/MFA/恢复码可能已被之后的安全操作撤销。重新审查并轮换管理员凭据、MFA/恢复码和部署会话秘密后才开放登录，不能因撤销 session 就声称全部旧凭据失效。
3. 对账快照到故障时刻间的所有收款、退款、争议、订阅和积分消费。快照之外的已支付/已消费事实不会凭空恢复；回调重放前核对渠道实际交易和本地幂等记录，不能重复授信。保留原库协助差异核对。
4. 核对所有未终结生成任务。快照中的 `queued` 可能在备份后已发给供应商，不能立即启动 dispatcher；保留未知状态、冻结金额和原报价，先人工/供应商对账。脚本**不**擅自假定全部成功、失败、退款或自动重发。
5. 私有图片不在数据库备份中。核对原持久图片盘、文件权限、过期时间、缺失文件与清理状态；不复制已过期内容，不延长 TTL。公开 Logo 等素材单独维护，不与用户文件混用。
6. 在隔离应用实际验证管理员重新登录、公开页面与发布版本、草稿隔离、余额/冻结/债务、历史授权和过期清理，然后才批准自己的应用实例切换到新路径。停止/切换/流量恢复需明确部署权限，不操作其他项目。

当前代码提供真实快照和离线准备；尚未提供自动灾难恢复的冻结门、跨渠道补账自动化或凭据整体轮换工具。它们不能用上述手册冒称已自动完成。隔离容器演练使用新建合成持久目录，范围与实际成功报告见 [容器验收](container-rehearsal.md)；完整支付灾难恢复仍需独立验收。

## 普通更新与回滚

普通代码/容器更新继续挂载原持久数据库和 `AI_ASSET_DIR`，不恢复旧快照、不重新 seed 覆盖配置，不删除数据卷。先保留最新已验证快照和旧镜像摘要；失败时优先回退应用镜像并保持现有数据，只在 schema 相容时这样做。确需数据恢复时使用上述新路径流程；绝不通过 `down -v`、清卷或直接复制覆盖在线库进行回滚。

当前 Dockerfile.web 已将三个 Node 维护脚本复制进 runtime 镜像，仍没有携带 pnpm。使用已核验的容器 ID 执行 `node scripts/admin-backup.mjs`，或者使用相同镜像的无网络维护容器与明确持久目录执行离线恢复；具体隔离示例见 [容器验收](container-rehearsal.md)。部署中的旧镜像没有自动更新，不要假设它已包含新脚本，也不要为维护把 Docker 控制权暴露给后台。
